# 프론트엔드 핵심 화면 및 공통 아키텍처 (Frontend UI Architecture)

이 문서는 터잡이 서비스의 순수 HTML, CSS, Vanilla JS 기반 프론트엔드 화면 구성과 폴더 구조를 정의합니다. 정적 웹 호스팅(Porkbun FTP) 환경에 최적화되어 있습니다.

## 1. 전역 디렉토리 구조 (Static Site)
프론트엔드 프로젝트는 별도의 빌드 도구 없이 브라우저에서 바로 실행 가능한 순수 정적 파일들로 구성됩니다.

```text
frontend/
├── index.html            # 랜딩 페이지 및 통합 진입점 (모달 로그인 포함)
├── search.html           # 네이버 지도 검색 화면 (지도 위 매물 상세 좌/우 슬라이딩 팝업 표출)
├── gallery.html          # 부동산 매물 갤러리 게시판
├── properties.html       # (갤러리 진입 전용) 매물 상세 정보, 공공데이터 조회 단독 화면
├── mypage.html           # 내 정보 및 관심 매물 관리 
├── admin.html            # 관리자 전용 페이지 (매물 등록/수정/삭제 및 예약 관리)
├── css/
│   ├── style.css         # 글로벌 & 공통 CSS (초기화, 폰트, 공통 변수)
│   ├── components.css    # 재사용 컴포넌트(버튼, 카드 등) 스타일
│   └── pages/            # 각 페이지별 개별 스타일
├── js/
│   ├── app.js            # 글로벌 공통 로직 (헤더/푸터 렌더링, 공통 유틸 등)
│   ├── auth.js           # 인증 상태 확인 API 래퍼, 모달 레이어 및 CORS `credentials: true` 적용된 Fetch 유틸
│   ├── components/       # 재사용 UI 컴포넌트 렌더링 함수 (JS 템플릿 리터럴 활용)
│   │   ├── header.js
│   │   ├── footer.js
│   │   └── login-modal.js # 공통 소셜 로그인 레이어 모달 컴포넌트
│   └── pages/            # 페이지별 독립적인 비즈니스 로직 및 DOM 조작
│       ├── search.js     # 네이버 마커, 클러스터링 로직 등
│       └── gallery.js    # 매물 API 호출 및 카드 UI 동적 생성
└── assets/               # 정적 파일 (이미지, 아이콘 등)
```

## 2. 주요 핵심 화면 설계 명세

### 2.1 랜딩 & 로그인 화면 (`index.html` + Login Modal)
*   **목적**: 서비스 진입 안내 및 레이어 모달(Layer Modal)을 통한 자연스러운 소셜 로그인 유도
*   **주요 로직**: 
    *   `index.html`은 Hero Banner와 서비스 설명 섹션을 제공합니다.
    *   페이지 상단 또는 본문의 로그인 버튼 클릭 시 별도의 페이지 이동 없이 `login-modal.js`를 통해 화면 중앙에 레이어 모달 폼이 나타납니다.
    *   모달 내의 소셜(네이버/카카오/구글) 버튼 클릭 시 백엔드 `/api/v1/auth/...` 엔드포인트로 리다이렉트되어 인증을 수행한 후 다시 현재 위치로 되돌아옵니다.

### 2.2 부동산 매물 이미지 갤러리 (`gallery.html`)
*   **목적**: 지번 주소를 포함한 등록 매물의 시각적인 썸네일 리스트 제공 (일반 사용자 조회 전용)
*   **주요 로직**: 
    *   `js/pages/gallery.js`에서 `/api/v1/properties` Fetch API를 호출합니다.
    *   가져온 JSON 데이터를 바탕으로 JS 템플릿 리터럴을 사용해 `<div class="property-card">...</div>` DOM 요소들을 동적으로 생성하여 화면에 추가합니다.
    *   생성된 카드 클릭 시 매물 고유 주소 및 위경도 값을 가지고 `properties.html?id=UUID` 주소로 화면을 전환하여 해당 매물의 단독 상세 페이지를 띄웁니다.

### 2.3 네이버 지도 검색 화면 (`search.html`)
*   **목적**: 일반 부동산 정보와 관리자가 등록한 컨설팅 매물을 지도 기반으로 검색/조회하고, 좌측 레이어드 팝업(슬라이딩 패널)으로 상세 정보를 시각화
*   **레이아웃 구조**:
    *   **헤더**: 고정 높이(예: 60px)의 공통 헤더 영역. 서비스 로고, GNB 메뉴, **지도 내 통합 검색 인풋**(주소/키워드 검색)을 포함합니다.
    *   **지도 영역**: 헤더 바로 아래부터 화면 하단까지 `height: calc(100vh - 60px)`로 뷰포트 전체를 차지합니다. 별도 스크롤 없이 지도가 전면에 노출됩니다.
    *   **좌측 슬라이딩 패널**: 지도 위에 `position: fixed` 또는 `position: absolute`로 겹쳐 렌더링. 닫힌 상태에서는 화면 밖으로 숨겨지고(`transform: translateX(-100%)`), 마커 또는 지도 클릭 시 트랜지션과 함께 좌측에서 슬라이드인됩니다. 패널 너비는 데스크탑 기준 360~400px, 모바일에서는 화면 전체 너비를 사용합니다.
*   **주요 로직 및 UI 배치** (`js/pages/search.js`):
    *   **초기 로드**: `search.html` 내 `<script src="https://openapi.map.naver.com/..."></script>`를 직접 로드한 뒤 `search.js`의 `initMap()` 함수로 지도를 초기화합니다.
    *   **통합 검색바 (주소 검색 + 키워드 검색)**:
        *   헤더 또는 지도 상단에 단일 `<input>` 검색 UI를 배치합니다.
        *   **주소 검색**: 입력값이 도로명/지번 형태로 판단될 경우(또는 항상 fallback으로) 네이버 지도 SDK의 [`naver.maps.Service.geocode()`](https://navermaps.github.io/maps.js.ncp/docs/naver.maps.Service.html)를 호출하여 좌표로 변환한 뒤 지도 중심을 이동시킵니다.
        *   **키워드 검색**: 장소명·업종명 등의 POI 검색은 네이버 지도 SDK의 [`naver.maps.Service.searchCoordinateToAddress()`](https://navermaps.github.io/maps.js.ncp/docs/) 또는 백엔드 프록시를 통한 **네이버 검색 API(지역 검색)** `GET /v1/search/local` 를 Fetch로 호출하여 결과 목록을 드롭다운으로 표출합니다.
        *   검색 결과 선택 시 해당 좌표로 지도 `panTo` 이동 및 마커 강조 표시.
        *   검색어 Input에 `input` 이벤트를 걸어 debounce(300ms)로 자동완성 후보를 드롭다운 목록으로 노출합니다.
    *   **지도 이벤트 바인딩**: 지도 이동(`dragend`) 및 줌 변경(`zoom_changed`) 시 현재 지도 바운더리를 백엔드 `/api/v1/properties/map?ne=...&sw=...` 로 요청하여 해당 영역의 매물 마커를 갱신합니다.
    *   **좌측 슬라이딩 패널 로직**: 별도의 상세 페이지(`properties.html`) 이동 없이 지도 내에서 모든 정보를 소화합니다.
        *   **일반 부동산/빈 땅**: 지도 상의 위치 클릭 시 `reverseGeocode`로 주소를 확인한 뒤 좌측 패널을 슬라이드인. 패널에는 공공데이터(공시지가, 실거래율, 토지이용규제)를 요약 표시합니다.
        *   **관리자 등록 매물 (커스텀 마커)**: 커스텀 마커 클릭 시 좌측 패널 슬라이드인. 패널에는 컨설팅 내용, 이미지 갤러리 슬라이드, 가격 정보, 공공데이터 결합 정보가 표시되며, 하단에 상담 예약 버튼(`POST /api/v1/reservations`)이 제공됩니다.
    *   **지적도 레이어 토글**: 지도 우측 상단(또는 지도 컨트롤 영역)에 **지적도 ON/OFF 버튼**을 배치합니다. 버튼 클릭 시 네이버 지도 SDK의 `naver.maps.MapTypeId.CADASTRAL` 타입을 전환하여 지적 경계선을 지도 위에 오버레이합니다. 일반 지도 위에 지적도 레이어를 겹쳐 표시하려면 `cadastralLayer` 서브맵타입을 사용하며, 토지 필지 경계 확인이 핵심 기능인 서비스 특성을 반영합니다.
    *   **패널 닫기**: 패널 상단 닫기(×) 버튼 또는 지도 외부 클릭 시 `transform: translateX(-100%)`로 패널을 닫습니다.

### 2.4 매물 상세 및 공공데이터 연동 화면 (`properties.html`)
*   **목적**: 갤러리 또는 외부 링크 진입 시 특정 매물에 대한 상세 컨설팅 기록과 결합 공공데이터를 지도 없이 풀 페이지 형태로 렌더링하고 상담 예약을 진행합니다.
*   **주요 로직**:
    *   초기화 시 `URLSearchParams`를 통해 `?id=UUID` 추출.
    *   `/api/v1/properties/:id` API를 호출하고 컨설팅 상세 정보, 이미지 갤러리, 실거래가, 토지이음 정보를 바인딩합니다.
    *   예약 버튼 클릭 시 DOM 기반 예약 모달 팝업/스텝퍼를 제공합니다.

### 2.5 마이페이지 (`mypage.html`)
*   **목적**: 내가 찜(관심)한 매물 목록, 프로필 정보, 과거/대기중인 상담 예약 리스트 표시
*   **주요 로직**:
    *   `auth.js`의 `/api/v1/users/me` 검증 API(HttpOnly 쿠키 기반)를 통해 사용자 인증 유무를 검증(미인증 시 `index.html`의 로그인 레이어 유도).
    *   사용자 프로필 컴포넌트 및 관심 매물, 예약 내역 탭을 Vanilla JS 탭 네비게이션으로 렌더링합니다.

### 2.6 관리자 페이지 (`admin.html`)
*   **목적**: 최고 관리자(ADMIN) 권한을 가진 사용자가 부동산 매물을 등록, 수정, 삭제하고 사용자들의 전체 상담 예약 내역을 관리
*   **주요 로직**:
    *   진입 시 `auth.js`를 통해 JWT 페이로드 내 권한(Role)이 `ADMIN`인지 검증하고, 권한 부족 시 `index.html`로 튕겨냅니다.
    *   부동산 컨설팅 매물 등록 폼을 제공하며 백엔드 `/api/v1/properties` API에 `POST/PATCH/DELETE` 액션을 수행합니다.
    *   이미지 업로드 및 지도 핀 지정을 통해 PostGIS 및 저장용 데이터를 조합하여 전송 구현.

## 3. UI/UX 구현 기본 원칙
*   **순수 CSS 디자인**: 프레임워크 제약 없이 퍼포먼스를 극대화하기 위해 순수 CSS3를 활용하며, `style.css`에 CSS 변수(`:root { --primary-color: #..., }`)를 적극 활용해 테마를 맞춥니다.
*   **컴포넌트화 지향**: Vanilla JS의 함수 기반 템플릿 리터럴을 통해 헤더, 푸터 등 반복되는 HTML 구조를 `app.js` 등에서 일괄 주입하여 중복 마크업을 최소화합니다.
*   모바일 환경 (Mobile-first) 대응을 필수로 하여, 갤러리 및 지도의 모바일 사용성을 최우선으로 CSS 미디어 쿼리를 구성합니다.
