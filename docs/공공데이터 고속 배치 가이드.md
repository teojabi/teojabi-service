# 공공데이터 고속 배치(Batch) 시스템 가이드

이 문서는 서울시 건축물대장 데이터를 스테이징 테이블(Staging Table)을 활용하여 고속으로 임포트하고 변환하는 배치 시스템의 구현 상세를 설명합니다.

## 1. 개요
대량의 CSV 데이터를 효율적으로 처리하기 위해 **TEXT 기반 스테이징 테이블**을 거쳐 운영 테이블로 이관하는 전략을 사용합니다. 이는 데이터 타입 불일치로 인한 임포트 중단을 방지하고 DB 엔진의 연산 능력을 활용해 데이터를 정제하기 위함입니다.

## 2. 주요 구성 요소

### 1) SQL 스크립트 (`database/init/05-optimized-import.sql`)
- **Staging Table**: 모든 컬럼이 `TEXT` 타입인 `UNLOGGED` 테이블을 생성하여 로깅 부하를 최소화하고 쓰기 속도를 극대화합니다.
- **Data Transformation**: `INSERT INTO ... SELECT` 문과 `CAST`, `NULLIF`, `TO_DATE` 함수를 사용하여 데이터를 정제합니다.
- **Upsert 로직**: `ON CONFLICT` 구문을 사용하여 기존 데이터는 업데이트하고 신규 데이터는 삽입합니다.

### 2) 배치 서비스 (`backend/src/public-data/public-data-batch.service.ts`)
- **스케줄링**: NestJS의 `@nestjs/schedule` 모듈을 사용하여 주기를 관리합니다. (현재 매주 일요일 새벽 3시)
- **외부 프로세스 실행**: `child_process`를 통해 시스템에 설치된 `psql` 클라이언트를 호출합니다.
- **인증 보안**: `PGPASSWORD` 환경 변수를 사용하여 셸 명령에 비밀번호가 노출되지 않도록 안전하게 인증을 처리합니다.

## 3. 실행 프로세스 (4단계)

1.  **Step 1: 환경 준비**: `psql -f` 명령으로 스테이징 테이블을 생성합니다.
2.  **Step 2: 벌크 로드 (\copy)**: `psql -c "\copy ..."` 명령으로 CSV 파일을 스테이징 테이블에 초고속으로 붓습니다.
3.  **Step 3: 데이터 변환 및 이관**: 스테이징 테이블의 데이터를 운영 테이블(`BuildingInfo`, `BuildingFloor`)로 정제하여 옮깁니다.
4.  **Step 4: 사후 정리**: 사용이 끝난 스테이징 테이블을 삭제하고 `ANALYZE`를 실행하여 쿼리 최적화 통계를 업데이트합니다.

## 4. 운영 및 주의사항

- **psql 의존성**: 서비스가 실행되는 환경에 `psql` 바이너리가 설치되어 있어야 하며, `public-data-batch.service.ts`의 `psqlPath`가 올바른지 확인해야 합니다.
- **파일명 영문화**: 한글 경로 인코딩 문제를 방지하기 위해 CSV 파일명은 반드시 영문(`seoul_building_info.csv`)으로 관리합니다.
- **메모리 및 디스크**: 대량 데이터 변환 시 일시적으로 디스크 사용량이 증가할 수 있으므로 충분한 공간을 확보해야 합니다.
